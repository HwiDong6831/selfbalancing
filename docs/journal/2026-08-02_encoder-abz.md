# 2026-08-02 : 엔코더 ABZ 전환 + 전원 보강 — 손상 해결

> **상태: 해결.** 밸런싱이 정상 동작하고 통신 오류가 사라졌다.
> 하드웨어와 소프트웨어 **양쪽을 고쳤다.**

| | 무엇 | 무엇을 해결했나 |
|---|---|---|
| 하드웨어 | 자기 인코더 전원부에 **0.1µF 세라믹 콘덴서** | 송신 전류로 생기던 전원 흔들림 |
| 소프트웨어 | 엔코더를 I2C → **ABZ (PCNT)** | I2C 버스 혼잡으로 인한 반응 지연 |

전원 문제의 원인 규명은 [2026-07-30](2026-07-30_wifi-power-dip.md) 참조.

---

## 왜 ABZ 로 옮겼나

**I2C 버스에 센서가 이미 3개다.** 여기에 엔코더까지 얹으면 한 루프에 거래가 4번이라
반응이 느려진다. 엔코더를 버스에서 빼면 그만큼 예산이 돌아온다.
PCNT 는 하드웨어가 펄스를 세므로 **읽기 대기가 0** 이다.

고장 크기도 줄어든다. I2C 는 "지금 각도" 를 통째로 받으므로 한 비트가 뒤집히면
45 / 90 / 180도가 틀어진다. ABZ 는 펄스를 세는 방식이라 하나 놓쳐도 **0.088도** 다.

대가는 **절대값 → 증분값** 이다. 부팅 시 위치를 모르므로 정렬 스윕이 기준을 잡아준다.

---

## PCNT 설계 — 회전수 누적이 필요 없다

카운터의 상·하한을 **±4096(한 바퀴)** 으로 걸면 한 바퀴마다 카운터가 스스로 0 으로
돌아간다. 그래서 **카운트가 곧 한 바퀴 안에서의 위치**가 되고, 회전수를 따로 누적하는
변수가 사라진다. 각도는 `count × 2π/4096` 한 줄로 나온다.

| 항목 | 값 |
|---|---|
| 핀 | A=21, B=22, Z=26 |
| 디코딩 | 2채널 4체배 |
| 글리치 필터 | 1µs (최고속 55rad/s 에서 펄스 간격 28µs) |

---

## 문제 1 : 카운트가 0 근처에 묶였다 ★

휠을 3바퀴 돌려도 카운트가 `-1` 과 `0` 만 오갔다.

**원인은 두 채널의 엣지 방향을 같게 건 것이었다.** 쿼드러처 4체배는 두 채널이 서로
반대 방향으로 세야 하는데, 공통 초기화 함수로 묶으면서 둘 다 같은 방향이 됐다.
A 가 센 만큼 B 가 되돌려 정확히 상쇄된다.

```c
channel_init(PIN_A, PIN_B, false);   // 상승 DECREASE / 하강 INCREASE
channel_init(PIN_B, PIN_A, true);    // 상승 INCREASE / 하강 DECREASE
```

### 진단이 결정적이었던 부분

배선과 코드 중 어느 쪽인지 못 가르고 있었다. **PCNT 를 거치지 않고 A/B 핀 전압을
직접 읽어** 제어 루프마다 바뀐 횟수를 셌다.

| 상태 | `AB변화` | 레벨 |
|---|---|---|
| 정지 | 0 | `A1 B0` 고정 |
| 회전 | 8~13 (루프 수와 비슷) | 계속 바뀜 |

**신호는 회전에만 반응했다.** 배선은 정상이고 세는 쪽이 틀렸다는 것이 한 번에 갈렸다.
이 계측이 없었으면 배선을 계속 의심했을 것이다.

## 문제 2 : Z 를 잡음으로 오판했다 ★

정지 상태에서 Z 인터럽트가 떠서 잡음으로 판단했다. 근거는 발생 빈도였다.

| 상태 | 구간 | Z | 간격 |
|---|---|---|---|
| 정지 | 14.3초 | 5회 | 2.9초당 1회 |
| 회전 | 7.2초 | 3회 | 2.4초당 1회 |

"돌리든 안 돌리든 비율이 같으니 회전과 무관하다" 고 결론냈다. **틀렸다.**

회전 구간에서 **실제로 몇 바퀴 돌았는지를 안 셌다.** 손으로 돌린 양이 적어 Z 가 그만큼만
뜬 것이었다. 나중에 제대로 돌리자 5.2초에 5회로 회전수와 정확히 맞았다.

정지 상태의 Z 도 설명된다. 회전자가 Z 표시 바로 위에 멈춰 있었고(Z 시점 카운트가 항상
0/1), 자기 인코더가 눈금 경계에서 한 칸씩 떨면서 Z 경계를 넘나든 것이다.

**분모를 안 맞춘 비교였다.** `2026-07-27` 에서 "루프 주기가 바뀌면 초당 몇 회는 비교가
안 된다" 로 배운 것과 같은 종류의 실수다.

---

## 한 바퀴 카운트 확정 — Z 카운트가 2784 로 고정

Z 는 한 바퀴에 정확히 같은 자리에서 나온다. 따라서 **Z 시점의 카운트가 안 밀리면
설정한 한 바퀴 값이 맞다.** 5회 모두 `2784` 였다.

넘김도 검증됐다. `4011 → 829` 는 실제로 914 카운트 진행이고,
0.104초에 914 카운트 = 2.1회전/초. 같은 줄의 `휠 12.6 rad/s`(2.0회전/초)와 맞는다.

MT6701 의 ABZ 최대 해상도가 1024PPR 이라 4096 의 배수일 가능성도 없다.

## 센서 축 변경

부착 방향이 바뀌어 기울기 평면이 YZ → **XY** 가 됐다.

| | 이전 | 지금 |
|---|---|---|
| 각도 | `atan2(-ay, -az)` | `atan2(ax, ay)` |
| 각속도 | `gx` | `gz` |

똑바로 선 자세에서 중력이 +Y 로 실려 `ay≈1g`, `ax≈0` 이므로 그대로 0도가 나온다.
이전 코드에 있던 `-ay, -az` 의 180도 뒤집기는 필요 없어져 뺐다.

## 배운 것

1. **하드웨어와 소프트웨어를 같이 봐야 한다.** 전원 흔들림은 콘덴서로, 버스 혼잡은
   구조 변경으로 잡았다. 어느 한쪽만으로는 안 끝났다
2. **신호가 없는 것과 잘못 세는 것은 다른 문제다.** 핀 전압을 직접 읽는 계측 하나가
   배선/코드를 갈랐다
3. **빈도를 비교할 때는 분모를 맞출 것.** 회전량을 안 세고 시간당 횟수만 봐서
   정상 신호를 잡음으로 판정했다
4. **기준 신호(Z)가 있으면 설정값을 검증할 수 있다.** 한 바퀴 카운트를 가정하지 않고
   실측으로 확정했다

## 남은 일

1. **Z 재동기화 미구현.** 지금은 Z 시점 카운트를 기록만 한다. 고속에서 펄스를 놓치면
   밀리므로 안전장치로 넣을 것. 조립이 끝나야 밀림을 측정할 수 있다
2. **3센서 voting 미구현.** 되돌려진 상태(`a0f17f9`)이고 제어는 채널 5 하나만 쓴다
3. `ENC_DIR` 은 `+1` 로 두고 있다. 오픈루프 정·역 시험으로 확인했다
4. 문서·주석의 "MPU6050" → MPU6500 정정 (WHO_AM_I `0x70`, 세 채널 모두 확인)
