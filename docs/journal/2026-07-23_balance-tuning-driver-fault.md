# 2026-07-23 : 밸런싱 튜닝 진행 + 모터 출력 상실

토크모드 밸런싱을 튜닝하던 중 모터 출력이 사라져 중단. 당시엔 드라이버 고장으로 판단했으나
**후속 확인 결과 원인은 배터리 전압 저하였다.** 아래 §후속 확인 참조.

---

## 진행 상황 (동작 검증됨, 전부 커밋)
- FOC 정렬 d축 교정 + 인코더 버스트 → 커뮤테이션 정상
- 자이로 + 상보필터 각도 추정 (똑바로=0, wrap 제거)
- 토크모드 상태피드백 `uq = K1·angle + K2·rate`
- 밸런스 setpoint 캘리브레이션 (시작 시 밸런스 자세 잡고 2초 → 그 각도를 0 기준)
- 각도 데드밴드 (±1°)

## 튜닝 상태 (미완)
- **중앙에 두면 ~1초 균형 유지하나, 혼자서 넘어짐** → 안정성/튜닝 문제 (모멘텀 한계 아님).
- 게인 K1=-2.0, K2=-0.2 까지 올림. 여전히 발산.
- 미검토: 데드밴드가 오히려 무복원 데드존→드리프트 유발 가능(DEADBAND 0 테스트 필요), setpoint 정밀도, 적분항.

## 실패한 실험: 디커플링 (기록)
- 가설: 복원 시 "턱 넘어감"이 커뮤테이션 275Hz 한계 때문.
- 시도: FOC 커뮤테이션(인코더+토크) 매 iter, MPU/밸런싱 5 iter마다 → ~670Hz.
- 결과: **복원 개선 0 + 새 소음(시이익)** → 되돌림.
- 교훈: 벽은 커뮤테이션 속도 아님. 그리고 **공유 I2C 버스에선 인코더 고속 읽기가 mux/MPU와 경합**해 고속 커뮤테이션 자체가 어려움(인코더가 SPI/ABZ 등 I2C 밖이어야 가능 = 하드웨어).

## 모터 출력 상실 (사실 기록)

> 이 절은 **당시 관측·판단을 그대로 남긴 것**이다. 결론은 §후속 확인 에서 뒤집혔다.

### 증상 (관측된 사실, 순서대로)
1. 튜닝 중 모터 토크 점점 약해짐 + "쉬이익" 소음.
2. 전원 OFF 후 손회전: 매끄러움. 모터 발열 없음(만졌을 때 안 뜨거움).
3. 구동(오픈루프): 조금 돌다 멈춰 진동. **커맨드 속도와 무관하게 동일.**
4. 정적 벡터 홀드(ud=6V, 전기각 0)에서 3상 출력 DC 전압 측정:
   - 시작 **3.6 / 3.5 / 3.5 V** → 한 상이 점점 감소해 0 → **셋 다 0V**.
   - 이 과정에서 소음 점점 작아지다 멈춤, 모터 정지.
5. 최종 상태: 3상 출력 전부 **0V**, 모터 무동작·무음.

### 측정으로 확인된 부품 상태
| 부품 | 상태 | 측정 근거 |
|---|---|---|
| 모터 | 정상 | 3상 저항 3쌍 모두 20Ω(균등), 손회전 역기전력 3쌍 균등 발전 |
| 배선 | 정상 | 3상 도통 OK |
| ESP32 | 정상 | 코드 계속 실행됨 |
| 드라이버(SimpleFOC Mini) | 출력 없음 | 3상 출력 전부 0V, 스위칭 안 됨 |

→ **당시 결론: 드라이버가 3상 출력을 상실.** (오판. §후속 확인)

### 원인 (당시)
- **미확인.** 측정으로 고장 사인을 특정하지 못함.
- 운용 조건 (사실만, 인과 주장 아님):
  - `UQ_LIMIT` = 11V 로 설정돼 있었음.
  - 모터 3상 저항 20Ω → 정지 시 전류 계산값 = 11V / 20Ω ≈ 0.55A.
  - 부팅 시 정렬 루틴이 d축 전압을 캘리브레이션 구간(~3.6s) 동안 지속 인가.
  - 고장 확인용 정적 벡터 홀드(ud=6V)를 인가한 상태에서 위 증상 4가 진행됨.

## 후속 확인 : 드라이버 고장 아님, 배터리 전압 저하

**드라이버는 멀쩡했다.** 같은 SimpleFOC Mini 로 이후 밸런싱·텔레메트리 작업을 정상 진행했다
(2026-07-25 일지).

### 기록된 사실을 다시 읽으면

증상 4의 전압 **추이**가 드라이버 고장보다 공급 전압 저하에 맞는다.
(절대값 3.6/3.5/3.5V 자체는 근거로 쓰기 어렵다. 멀티미터는 PWM 평균을 읽고, 상-GND 전압은
0.5 중심 시프트와 역Clarke 분배가 섞인 값이라 명령한 `ud=6V` 와 직접 비교되지 않는다.)

- 3상이 **점진적으로** 감소해 0V 로 갔다. 소자가 죽으면 보통 즉시 0 이지, 서서히 내려가지 않는다.
- 증상 1의 "토크가 점점 약해짐"도 같은 곡선이다.
- 전원을 정리하고 다시 시험했을 때 같은 드라이버가 정상 동작했다.

### 왜 이 증상이 나오나

`foc.c` 는 duty 를 `u / V_SUPPLY + 0.5` 로 만드는데 `V_SUPPLY` 가 **11.3f 하드코딩**이다.
실제 배터리가 그보다 낮으면:

- 같은 uq 명령이 실제로는 더 낮은 전압으로 인가된다 → 토크가 명령보다 약함.
- 배터리가 계속 닳으면 이 괴리가 커진다 → 토크가 **점점** 약해짐.
- 펌웨어는 이 사실을 알 방법이 없다. 로그에는 정상 uq 가 찍힌다.

### 교훈

- **모터가 약해지면 배터리 전압부터 잰다.** 부품 고장을 의심하기 전에.
- 정지 상태 홀드는 역기전력이 없어 전류가 가장 크다. 배터리 소모도 이때 가장 빠르다.
- `V_SUPPLY` 하드코딩은 배터리 전압이 변하는 한 **튜닝 재현성을 깬다**. 어제의 K1·K2 가
  오늘 다르게 동작한다. 게인이 안 잡힐 때 후보로 기억해 둘 것.

## 다음 작업

### 안전 조치
1. ~~`UQ_LIMIT` ≤ 4V로 복귀~~ — 취소. 고장 원인이 과전류가 아니었으므로 11V 유지.
2. **정렬 후 캘리브레이션 중 모터 끄기** — 적용 완료. 정렬 d축 전압을 캘리브레이션(~2.6s)
   내내 홀드하던 것을 `foc_enable(false)` 로 끊었다. 배터리 소모·발열 모두 줄어든다.

### 튜닝 재개
3. **튜닝 전 배터리 전압 확인.** 전압이 다르면 같은 게인이 다른 토크를 낸다.
4. 게인 튜닝: 우선 **DEADBAND 0**으로 순수 K1·angle+K2·rate 안정성 확인 → K2(감쇠) 위주
   튜닝 → setpoint 정밀도.
5. 여전히 발산이면: 적분항 / 휠속도항(K3) 검토, 상보필터 계수·지연 점검.
