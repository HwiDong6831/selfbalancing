# 작업 일지 - 2026-07-15 : FOC 오픈루프 브링업 (ESP-IDF 맨땅 구현)

BLDC 모터를 ESP-IDF에서 **맨땅 FOC(라이브러리 없이)**로 구동. 오픈루프 회전까지 검증한 기록.
시행착오를 순서대로 정리 — 각 문제의 원인과 해결, 그리고 배운 점(면접 대비).

---

## 0. 목표와 방향 결정

- 목표: SimpleFOC Mini + 2804 BLDC를 ESP-IDF C로 직접 제어. Step 1 = 오픈루프 회전 검증.
- **맨땅 구현 결정 이유**: 임베디드 SW 포트폴리오. 라이브러리(esp_simplefoc)로도 IDF에서 가능하지만,
  PWM 페리페럴/제어 루프를 직접 다루는 경험이 기술력 어필에 유리.
- **중요한 전제**: SimpleFOC Mini = DRV8313 기반 **3-PWM 드라이버, 전류 센서 없음**.
  → 전류 루프가 없는 **전압 모드 FOC**만 구현. FOC의 제일 어려운 부분(전류 측정→PI 전류제어)이 빠짐.
  → 이 하드웨어 특성 덕에 맨땅 구현이 감당 가능한 난이도가 됨.

## 1. 컴포넌트 구조

`components/foc/` 신규 (flat 레이아웃):
- `foc.h` / `foc.c` : 전압모드 FOC 드라이버
- `CMakeLists.txt` : `REQUIRES esp_driver_ledc esp_driver_gpio`

핵심 API:
- `foc_set_phase_voltage(ud, uq, angle_el)` — 전압 벡터 → 3상 duty (FOC 핵심, 클로즈드루프도 재사용)
- `foc_openloop_velocity(vel, dt)` — 인코더 없이 전기각 강제 적분 (검증용)
- `foc_init` / `foc_enable`

알고리즘 파이프라인:
```
(ud, uq) + 전기각 → 역 Park → (α,β) → 역 Clarke → 3상 전압 → duty(=u/V_SUPPLY + 0.5) → LEDC
```

## 2. LEDC vs MCPWM 선택

- 3-PWM 드라이버라 데드타임/상보출력이 드라이버 칩 내부 처리 → MCPWM 강점 불필요.
- LEDC(단순)로 충분. 상세: [2026-07-15_ledc-vs-mcpwm.md](./2026-07-15_ledc-vs-mcpwm.md)

## 시행착오 기록 (순서대로)

### 문제 1. PWM 주파수 vs 해상도 충돌
- 시도: 20kHz(가청 위) + 12비트 해상도.
- 증상/원인: LEDC 최대 주파수 = `클럭(80MHz) / 2^해상도`. 12비트면 `80M/4096 ≈ 19,531Hz`가 한계.
  20,000Hz 요청은 이 한계를 초과 → `ledc_timer_config` 실패 위험.
- 이유: 클럭 고정 상태에서 해상도를 높이면 한 주기가 길어져 주파수 상한이 내려감(트레이드오프).
- 해결: **11비트로 낮춤**(2048단계, 최대 39kHz) → 22kHz 사용 가능.
  `PWM_FREQ_HZ=22000, PWM_RES=LEDC_TIMER_11_BIT, DUTY_MAX=2047`.
- 교훈: PWM 페리페럴에서 주파수와 해상도는 독립이 아니다. 고정 클럭에서 둘은 반비례.

### 문제 2. 코드 리뷰에서 발견한 버그 3개
직접 작성 후 점검 과정에서:
1. `foc_init`: `ESP_ERROR_CHECK(&cfg)` — `gpio_config()` **호출 자체가 누락**. 구조체 포인터를
   esp_err_t로 넘겨 부팅 즉시 abort 날 상태였음. → `ESP_ERROR_CHECK(gpio_config(&cfg))`.
2. `foc_init`: `ledc_channel_config_t`에서 `.duty` **중복 지정**(엉뚱한 값 후 0). 정리.
3. `foc_enable`: `for(i<2)` — 3상 중 **2개만** duty 0 처리. → `i<3`.
- 교훈: ESP-IDF는 `xxx_config_t` 채우기 → `xxx_config()` **호출**이 한 세트. 구조체만 채우고 호출을 빼먹기 쉬움.

### 문제 3. 모터가 회전 안 하고 떨기만 함 (제일 중요)
- 증상: 전원 인가 시 회전 없이 제자리 진동(cogging).
- 원인 분석(숫자로): FreeRTOS **기본 tick = 100Hz** → `vTaskDelay(1)` = **10ms** → 루프 100Hz.
  - 목표 10 rad/s(축) × pole_pairs 7 = 70 rad/s(전기) ≈ 11.1 전기회전/초.
  - 한 스텝(10ms)당 전기각 증가 = 70 × 0.01 = **0.7 rad ≈ 40°**.
  - 전기 1회전을 **9스텝**으로만 쪼갬 → 자기장이 40°씩 뚝뚝 점프 → 회전자가 못 따라가 진동.
  - 부드러운 회전엔 전기 1회전당 20~50스텝 필요 → 루프 1kHz 이상 요구.
- 해결: `CONFIG_FREERTOS_HZ = 1000` (menuconfig) → `vTaskDelay(1)` = 1ms = 1kHz 루프.
  (esp_simplefoc 공식 문서도 tick 1000Hz 필수라고 명시)
- 교훈: 실시간 제어 루프에서 **업데이트 주파수 vs 전기 주파수**의 비가 부족하면 이산화(discretization)로
  코깅/진동 발생. 제어 대상의 주파수를 알고 샘플링/갱신율을 그에 맞춰야 함.

### 문제 4. tick 올린 뒤에도 초기 진동
- 증상: 회전은 시작하나 초반에 떨림.
- 원인: 오픈루프는 회전자 위치를 모른 채 자기장을 강제 회전. 정지 상태에서 갑자기 고속(11 전기회전/초)을
  명령하면 회전자가 이미 빠른 자기장을 **처음부터 붙잡지 못하고 미끄러짐(slip)**.
- 해결: **속도 램프업** 추가. `vel`을 0에서 `accel=5 rad/s²`로 증가시켜 2초에 걸쳐 목표 도달.
  자기장이 서서히 빨라져 회전자가 처음부터 락(lock) 유지.
- 교훈: 오픈루프 기동은 저속 시작 또는 램프가 필수. 피드백이 없으니 급격한 명령을 못 따라간다.

### 문제 5. 램프 후에도 잔여 떨림 (오픈루프의 태생적 한계)
- 증상: 회전은 하나 미세 진동 잔존.
- 원인(근본): 오픈루프 전압모드의 구조적 한계.
  - 위치 피드백 없음 → 전압 벡터가 회전자와 최적 정렬 안 됨 → 토크 리플.
  - 코깅 토크(모터 자체 자기 걸림) 보정 불가. 저속·저전압일수록 두드러짐.
  - 고정 전압(2V) 인가 → 속도 무관하게 같은 전압 → 저속 구간 덜컹.
- 완화(제거는 불가): 구동 전압 소폭 ↑(코깅 극복, 발열 증가 감수), 극저속 구간 회피.
- 근본 해결: **클로즈드루프 FOC** — 다음 단계.

## 면접용 핵심 포인트 (요약)

- **전압모드 vs 전류모드 FOC**: 전류 센서 유무로 갈림. 우리 드라이버는 센서 없어 전압모드 → 전류 루프 생략.
- **PWM 주파수/해상도 트레이드오프**: 고정 클럭에서 `f_max = clk / 2^res`. 실제로 겪고 11비트로 조정.
- **LEDC vs MCPWM 판단**: 3-PWM 드라이버라 데드타임 불필요 → 단순한 LEDC 선택(근거 있는 결정).
- **제어 루프 주파수의 중요성**: 100Hz→1kHz 변경으로 코깅 해결. 이산화/샘플링율을 숫자로 분석.
- **오픈루프 vs 클로즈드루프**: 오픈루프의 한계(위치 피드백 없음→토크 리플/코깅)를 이해하고 단계적으로 접근.
- **디버깅 방법론**: 증상→숫자로 원인 계산→해결. 추측이 아니라 정량 분석으로 원인 특정.
