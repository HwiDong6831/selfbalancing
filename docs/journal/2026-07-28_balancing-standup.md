# 2026-07-28 : 밸런싱 — 혼자 서다

> **상태: 성공.** 손을 놓아도 스스로 균형을 유지한다.

최종 게인:

| | 값 | 역할 |
|---|---|---|
| `BAL_K1` | **−4.0** V/도 | 기울어진 만큼 되민다 |
| `BAL_K2` | **−1.0** V/(도/s) | 넘어지는 속도를 보고 미리 막는다 |
| `BAL_K3` | **+0.3** V/(rad/s) | 휠이 한쪽으로 감기면 목표 자세를 옮긴다 |
| `DEADBAND` | **0.0** 도 | 껐다 (§1) |
| `UQ_LIMIT` | 6.0 V | |

---

## 진행 방식

부호가 반대면 기울수록 넘어지는 쪽으로 세게 밀어붙인다. 로그를 보고 알아차릴 시간이 없다.
그래서 모터를 물리기 전에 단계를 나눴다.

| 단계 | 내용 | 확인한 것 |
|---|---|---|
| 3-A | `DRIVE_MOTOR 0` — 드라이버 EN 을 끄고 `uq` 를 계산해 찍기만 | 각도·각속도 부호가 서로 맞는가 |
| 3-B | `UQ_LIMIT 3V` 로 낮추고 손으로 잡은 채 구동 | 휠이 도는 방향이 복원 방향인가 |
| 3-C | 게인 튜닝 | |

**3-A 에서 제어 루프를 따로 만들지 않은 것이 핵심이다.** `foc_apply_torque()` 까지 그대로
호출하고 드라이버 EN 만 껐다. 계측용 루프를 따로 짰다면 실제로 돌릴 코드와 다른 코드를
검증하게 된다. 노이즈 조사([2026-07-27](2026-07-27_foc-noise-isolated.md))에서 진단 모드가
여러 개 얹혀 결론이 안 나던 것과 같은 함정이다.

3-A 판정: 왼쪽으로 기울일 때 각도 +, 각속도 + 로 **부호가 일치**했다.
자이로 축이 틀렸다면 상보필터 안에서 자이로 적분과 가속도 각도가 서로 반대로 당겨
각도가 밀리거나 튄다. 그런 증상이 없었으므로 축(`gx`, `ay`/`az`)이 맞다.

## 1. 데드밴드가 첫 1초를 죽이고 있었다 ★

첫 폐루프는 0.7초 버티고 넘어졌다. 10Hz 로그를 찍자 원인이 한 줄에 드러났다.

```
10.9초  각도 0.9도  각속도 4.3도/s  uq -1.74V
11.0초  각도 1.4도  각속도 0.4도/s  uq -3.04V   ← 각속도는 1/10 인데 uq 는 2배
```

계산이 정확히 맞는다.

| 시점 | 각도 | 계산 | 로그 |
|---|---|---|---|
| 10.9초 | 0.9도 (데드밴드 안) | `0 + (-0.4×4.3)` = −1.72 | −1.74 |
| 11.0초 | 1.4도 (밖) | `(-2.0×1.4) + (-0.4×0.4)` = −2.96 | −3.04 |

`|각도| < 1.0` 인 동안 **각도항이 완전히 꺼져 있었다.** 작동한 건 감쇠뿐이다.

**감쇠만으로는 못 세운다.** 넘어지는 속도를 늦출 뿐 되돌리지 못한다. 도립진자는 위치
되먹임이 있어야 복원된다. 그 1초 동안 휠은 이미 −9.5 rad/s 까지 감겨 예산을 축내고 있었다.

`DEADBAND` 를 0 으로 바꾼 결과:

| | 1.0도 | 0 |
|---|---|---|
| 각도 0.1 → 1.0도 걸린 시간 | 0.65초 | **1.45초** |
| 각도 0.9도일 때 휠 속도 | −9.5 | **−22.7** |

저항 시간이 2.2배가 됐다. 우려하던 떨림은 거의 없었다(정지 구간에서 `uq` ±0.3V).

데드밴드는 미세 진동을 막으려고 넣은 것이었는데, **복원력이 0 인 구간을 만드는 대가**가
훨씬 컸다. 주석에도 재검토 대상으로 적혀 있던 항목이다.

## 2. 게인 크기 — 전력을 언제 쓰느냐의 문제

데드밴드를 껐는데도 양상은 같았다. 각속도가 한 번도 음수로 내려가지 않았다.

```
11.7초  1.5도/s   ← 초기 기울기
11.8초  0.3도/s   ← 늦추는 데는 성공
12.5초  1.5도/s   ← 다시 벌어짐
13.3초  6.5도/s   uq -5.24V  ← 아직 포화 아닌데 지고 있다
13.4초  10.6도/s  uq -6.00V
```

**늦추기만 하고 되돌리지 못했다.** 그리고 포화되기 전에 이미 졌다 — 13.3초에 0.76V 여유가
있는데도 각속도가 커진다.

전압을 언제 쓰는지가 문제였다.

| 시점 | 각도 | 쓰는 전압 | 여유 |
|---|---|---|---|
| 11.7초 | 0.1도 | 0.70V | 88% 남음 |
| 13.4초 | 1.8도 | 6.00V | 0% |

**초반 1.3초 동안 힘의 10~25% 만 쓰고 있었다.** 전력을 다 쏟는 시점이 1.8도인데 그때는
각속도가 10도/s 라 관성 때문에 못 세운다.

도립진자는 작을 때 잡아야 한다. 기울기가 커지면 중력 토크도 커지고 이미 붙은 속도도
되돌려야 해서, 전압을 다 써도 늦다.

**사용자 관측이 방향을 정했다** — "초기에 거의 반대쪽으로 넘어갈 정도로 순간 토크를 크게
주고 다시 보정하는 게 필요해 보인다". 이건 별도 알고리즘이 아니라 게인 크기 문제다.

`K1` 을 올려 6V 도달 기울기를 3.0도 → 1.0도로 당겼다.

## 3. K2 는 잡음 증폭기다 ★

`K1`·`K2` 를 같이 3배로 올리자 **모터에서 갈리는 소리**가 났다. 버티는 시간은 늘었다.

처음엔 과변조를 의심했다. `foc.c` 가 전압을 duty 로 바꿀 때 선형 한계가 `V_SUPPLY / 2` 라,
`uq` 6.0V 가 그 한계(당시 설정 11.3V 기준 5.65V)를 넘어 사인파 꼭대기가 잘리고 있었다.

**틀렸다.** 배터리를 재니 11.6V 였고, 그러면 한계가 5.8V 라 3.4% 만 넘는다. 그 정도로
그런 소리는 안 난다. (다만 `V_SUPPLY` 가 11.3 으로 낡아 있던 건 사실이라 11.6 으로 고쳤다.
명령보다 2.7% 높은 전압이 나가고 있었다.)

진짜 원인은 **채터링**이었다.

`rate` 는 자이로 raw 값이라 항상 잡음이 섞여 있다. `K2 = 0.4` 일 때 ±0.2V 수준이던 것이
`K2 = 3.0` 에서는 **±1.5V 짜리 명령**이 된다. `uq` 가 기울기와 무관하게 초당 수십 번
뒤집히고, 전압 벡터가 180도씩 반전되며 코일 전류가 계속 방향을 바꾼다. 그게 소리였다.

**떨림 크기는 `K2` 값만으로 정해진다. `K1` 과 무관하다.** 잡음이 들어오는 창구가
각속도항 하나뿐이기 때문이다. 각도 신호는 자이로를 적분한 값이라 훨씬 조용하다.

그래서 `K1` 은 높게 두고 `K2` 만 −3.0 → −2.0 → **−1.0** 으로 내렸다. 소리가 사라졌고
2초를 버텼다.

> 감쇠가 모자라면 `K2` 를 올리는 게 아니라 **각속도 신호를 걸러야 한다.**
> 자이로 잡음은 넓은 주파수에 퍼져 있고 실제 기울기 변화는 훨씬 느리므로,
> 20~30Hz 저역통과로 잡음만 깎고 감쇠는 유지할 수 있다. 이번엔 필요 없었다.

## 4. K3 — 부호가 반대였다 ★

2초를 버티지만 **한쪽으로 조금씩 밀리다 넘어졌다.** 휠 속도가 처음부터 끝까지 한 방향으로만
증가하고 한 번도 되감기지 않았다.

똑바로 선 자세를 `각도 0` 으로 잡았지만 **진짜 균형점이 거기가 아니다.** 조립 오차·무게중심
때문에 0.1~0.3도쯤 어긋나 있다. 제어기는 각도를 0 으로 유지하려 하고, 그 자세는 실제로는
살짝 기운 상태다. 기운 자세를 유지하려면 휠을 계속 더 빠르게 돌려야 하는데 휠 속도에는
한계(약 55 rad/s)가 있다. 닿는 순간 토크가 사라진다.

**버티는 시간만 늘어날 뿐 결말은 정해져 있었다.**

기준 각도를 손으로 더 정확히 잡는 건 답이 아니다. 눈으로 0.1도를 맞출 수 없고 조립을
건드릴 때마다 다시 해야 한다.

해법은 휠 속도를 되먹이는 것이다. **휠이 한쪽으로 계속 감긴다는 것 자체가 "기준이 틀렸다"는
신호**이므로, 그 신호로 목표 자세를 옮기면 제어기가 스스로 진짜 균형점을 찾아간다.

```c
uq = K1*angle + K2*rate + K3*wheel_vel;
```

### 두 가지가 예측과 달랐다

**부호.** 나는 "음수 휠 속도를 감속시키려면 양수 토크가 필요하므로 K3 는 음수" 로 유도해
`-0.05` 를 제안했다. **실기에서는 양수가 맞았다.** 유도가 틀렸다.

**크기.** `0.05` 를 제안했는데 실제로 동작한 값은 **`0.3`, 6배**다.

부호를 계산으로 정할 때는 휠 토크 방향과 몸체 반동 방향, 엔코더 증가 방향, 정렬 오프셋이
모두 얽힌다. 이 프로젝트에서 부호를 계산으로 맞춘 적이 한 번도 없다
(`BAL_K1` 도 "실기 확인해 반대라 음수" 로 적혀 있다). **부호는 재는 것이지 유도하는 게 아니다.**

`K1` 은 −6.0 에서 **−4.0** 으로 내렸다. K3 가 붙으면서 과했다.

## 배운 것

1. **복원력이 0 인 구간을 만들지 말 것.** 데드밴드가 첫 1초를 통째로 죽였다
2. **전력을 언제 쓰는가가 얼마나 쓰는가보다 중요하다.** 다 쓸 때쯤이면 늦다
3. **잡음이 들어오는 창구를 특정할 것.** 떨림은 `K2` 하나로 정해졌다. `K1` 을 같이 내렸다면
   원인을 못 찾고 성능만 잃었을 것이다
4. **부호는 실기에서 잰다.** 계산으로 두 번 틀렸다(`BAL_K1`, `BAL_K3`)
5. **10Hz 로그가 결론을 만들었다.** 0.7초짜리 현상을 1초에 한 줄로는 볼 수 없다.
   창 길이를 바꿀 거면 `loop Hz` 처럼 창 길이에 의존하는 지표도 같이 고쳐야 한다

---

## 알려진 한계

- **`uq` 6.0V 는 선형 한계(`V_SUPPLY / 2` = 5.8V)를 3.4% 넘는다.** 사인파 꼭대기가 살짝
  잘린다. 더 필요하면 **SVPWM**(공간벡터 변조)으로 약 15% 더 뽑을 수 있다
- 휠 최고 속도 약 55 rad/s. 큰 외란을 받으면 여전히 포화될 수 있다
- 센서는 mux 채널 0 하나만 쓴다. 3개 voting 은 미구현
