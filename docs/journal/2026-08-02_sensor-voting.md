# 2026-08-02 : 센서 3개 voting — 신호 단위 판정

> **상태: 구현·빌드·호스트 테스트까지. 실기 검증은 아직.**

MPU 3개를 달아 놓고 제어에는 mux 채널 하나만 쓰고 있었다. 나머지 둘은 대시보드에 숫자만
띄우는 장식이었다. 이번에 셋을 전부 제어에 넣었다.

여기서 말하는 **voting** 은 센서 여러 개의 값을 서로 비교해 이상한 값을 골라내고 나머지로
판단하는 다수결 방식이다. **mux** 는 하나의 통신선(I2C)을 여러 장치에 번갈아 붙여 주는
전환기다.

---

## 왜 필요했나

읽기가 성공했다고 나와도 값만 깨져 오는 경우가 있다. 전송 중 비트 하나가 뒤집히면 값이
2048 이나 16384 처럼 딱 2의 거듭제곱만큼 통째로 튄다. 함수 반환값은 성공이므로 통신 오류로는
안 잡히고, 그대로 각도 계산에 들어가 기울기를 밀어버린다.

**센서 한 개로는 이걸 알아낼 방법이 없다.** 값이 틀렸다는 걸 알려면 비교할 상대가 있어야
한다. 3개를 다는 이유가 여기 있다 — 여분이 아니라 상호 검증이다.

---

## 1. 어디서 투표할까 — 원시값이냐 추정각이냐

두 가지 후보가 있었다.

- **A안 원시값 단계(채택):** 센서 3개의 raw 값을 비교해 융합한 뒤, 상보필터는 하나만 돌린다.
- **B안 추정각 단계:** 센서마다 필터를 하나씩 돌려 각도 3개를 만들고 그 각도들을 비교한다.

**A안을 택한 이유 두 가지.**

첫째, **상보필터는 값을 부드럽게 만드는 장치다.** 비트 뒤집힘 같은 순간적인 튐이 필터를 한 번
통과하면 크기가 줄어들어, 정작 잡아내야 할 이상치가 임계값 아래로 숨는다. 애초에 잡으려던 게
"필터에 들어가서 각도를 밀어버리는 값" 이니 필터 **앞**에서 걸러야 맞다.

둘째, `balance_estimate_angle()` 은 상보필터 누적값을 함수 안 `static` 변수 하나로만 갖는다.
B안이면 센서 세 개가 이 값을 서로 덮어쓰므로 센서별 상태 분리부터 해야 한다. A안은 필터를
하나만 쓰므로 **이 문제가 아예 생기지 않는다.**

---

## 2. 무엇을 한 덩이로 볼까 — 센서 단위냐 신호 단위냐 ★

이번 작업의 핵심 결정이다.

- **센서 단위:** 축 하나라도 어긋나면 그 센서를 통째로 배제한다.
- **신호 단위(채택):** 가속도쌍 `(ax, ay)` 과 자이로 `gz` 를 **따로** 투표한다.

**신호 단위를 택한 이유.**

| 근거 | 내용 |
|---|---|
| 부품이 다르다 | 가속도계와 자이로는 한 칩 안의 **별개 소자**다. 실제로 한쪽만 고장난다 |
| 멀쩡한 값 낭비 | 센서 단위면 자이로 하나 어긋났다고 그 센서의 멀쩡한 가속도까지 버린다 |
| 이미 반쯤 그랬다 | 임계값이 벌써 신호별로 다르다 — 가속도 1500, 자이로 300 |
| 역할이 다르다 | 각도는 느린 보정용, 자이로는 `K2` 로 곧장 들어가는 빠른 항이다 |

**대신 `ax` 와 `ay` 는 따로 떼지 않고 한 덩이로 묶었다.** 이 둘은 `atan2(ax, ay)` 로 묶여
각도 하나를 만든다. 따로 투표하면 `ax` 는 센서 0·1 에서, `ay` 는 센서 0·2 에서 나오는 식이
되어 **어떤 센서도 실제로 본 적 없는 조합**이 만들어진다.

치르는 대가도 있다. 판정 결과가 하나에서 둘로 늘어나 텔레메트리 JSON 과 대시보드 표시가
그만큼 늘고, "몇 번 센서가 고장" 이라는 한 줄 진단이 "몇 번의 자이로가 고장" 으로 쪼개져
눈으로 훑기에 조금 덜 직관적이다. 그래도 멀쩡한 센서를 버리지 않는 쪽이 낫다고 봤다.

## 3. 비교하려면 먼저 영점을 맞춰야 한다

세 센서를 그냥 비교하면 안 된다. 개체차 때문에 **정상일 때도 값이 다르다.** 보정 없이
비교하면 그 개체차가 그대로 불일치로 잡혀 멀쩡한 센서가 배제된다.

자이로와 가속도를 다르게 다뤄야 했다.

| | 처리 | 이유 |
|---|---|---|
| 자이로 | 측정한 영점을 **통째로** 뺀다 | 정지 상태에서 0 이어야 하는 값이다 |
| 가속도 | 세 채널 평균의 **중앙값 대비 차이만** 뺀다 | 중력이 걸려 있다. 통째로 빼면 각도 정보까지 지워진다 |

가속도까지 통째로 뺐다면 `ay` 의 1g 성분이 사라져 기울기를 못 잰다. 지워야 하는 건 물리값이
아니라 센서 사이의 어긋남뿐이다.

이 보정이 들어가면서 `measure_gyro_bias()` 가 `measure_cal()` 로 커졌고, 이제 채널 3개를
전부 읽으므로 측정 시간이 약 1.2초에서 1.6초로 늘었다.

### 기준 각도도 같은 영점을 써야 한다

`measure_setpoint()` 은 로봇을 똑바로 세운 채 필터를 수렴시켜 "진짜 똑바로" 의 센서값을 잡는
함수다. 이 함수만 채널 0 의 날값으로 재면, 제어 루프는 중앙값 기준으로 융합한 값을 쓰는데
기준만 다른 곳을 보게 된다.

**그 차이가 수백 LSB, 각도로 1~2도다.** 각도 게인 `K1` 이 -4 V/deg 이므로 무시할 수 없어서,
`measure_setpoint()` 에도 같은 영점을 넘기도록 고쳤다.

## 4. 임계값은 재서 정했다

"얼마나 벌어지면 이상치인가" 를 감으로 정할 수 없어서 실측했다. 중앙값 대비 최대 편차를
정지·기울임·밸런싱 중에 각각 쟀다.

| | 정상 편차 [LSB] | 임계값 | 여유 |
|---|---|---|---|
| 가속도 | 109 ~ 490 | **1500** | 3배 |
| 자이로 | 29 ~ 150 | **300** | 2배 |

가속도 1500 이면 2048 짜리 비트 뒤집힘도 걸린다.

**여기서 임계값을 좁히고 싶은 유혹을 참아야 한다.** 세 센서는 mux 로 전환해 가며 읽으므로
서로 약 1ms 씩 어긋난 시점의 값이다. 가만히 있을 때는 문제가 안 되지만 급변 구간에서는 1ms
차이만으로도 정상값이 벌어진다. 그 폭을 재보지 않고 조이면 **외란에 반응해야 할 바로 그
순간에 FAIL 로 멈춘다.** 안전장치가 가장 필요한 순간에 꺼지는 셈이다.

---

## 5. 판정은 셋 중 하나

| | 뜻 | 동작 |
|---|---|---|
| `OK` | 3개 전부 서로 일치 | 셋 평균 |
| `DEGRADED` | 1개 배제, 나머지 둘은 일치 | 둘 평균. **여전히 상호 검증됨** |
| `FAIL` | 다수결 불가 | 값을 내지 않는다. 호출자가 직전 값 유지 |

`DEGRADED` 가 성능 저하가 아니라는 점이 중요하다. 둘이 서로 일치하는 한 검증은 계속된다.
검증이 끊기는 건 `FAIL` 뿐이다.

### 짝이 2개면 왜 FAIL 인가

서로 일치하는 짝의 개수를 세서 판정한다. 3개면 `OK`, 1개면 `DEGRADED` 다. 그런데 **2개일 때가
있다** — 0~1 은 일치, 1~2 도 일치인데 0~2 는 불일치인 사슬 모양이다.

이때 1번이 가운데에 있는 정상값인지, 아니면 0번과 2번 중 하나가 틀린 것인지 **가릴 근거가
없다.** 그래서 `FAIL` 로 둔다.

### FAIL 은 "값이 없다" 가 아니다

`FAIL` 은 "맞는지 확인할 수 없다" 는 뜻이다. 안전 필수 분야라면 여기서 안전 상태로 전환하지만,
**도립진자는 토크를 끊는 순간 넘어진다.** 그래서 `tilt`/`rate`/`uq` 를 갱신하지 않고 직전
명령을 그대로 이어간다.

특히 세 개가 전부 읽기 실패하면 값이 전부 0 인데, `atan2(0, 0)` 이 0 이라 **"똑바로 서
있다"** 로 읽힌다. 넘어지는 중에 복원 토크가 사라지는 최악의 오작동이다. 값을 그냥
흘려보내면 이 함정에 그대로 빠진다.

## 6. 호스트 테스트

`voting` 컴포넌트는 ESP-IDF 에 의존하지 않는 순수 C 로 짰다. 하드웨어 없이 PC 에서 바로
컴파일해 돌릴 수 있다.

```
cd esp/components/voting/test
gcc -std=c11 -Wall -Wextra -I.. test_voting.c ../voting.c -o test_voting && ./test_voting
```

9건을 덮었다 — 셋 다 일치, 하나만 튐, 사슬(짝 2개), 셋 다 어긋남, 임계값 경계, 읽기 실패
1개·2개, 안 보는 축 무시, 그리고 **자이로만 고장난 센서의 가속도가 살아남는지.** 마지막
항목이 이번 설계 결정을 그대로 검증한다.

## 7. 서버 계약이 바뀌었다

판정이 둘로 늘어나면서 JSON 모양이 바뀌었다.

```
이전  "voting":{"result":"ok","used":[...],"rejected":[...]}
이후  "voting":{"accel":{"result":...,"used":[...],"rejected":[...]},
                "gyro" :{"result":...,"used":[...],"rejected":[...]}}
```

`SensorFrame.Voting` 을 중첩 record 로 바꾸고 대시보드는 가속도·자이로 배지를 따로 띄운다.
`SensorFrameParseTest` 도 새 모양으로 고정했다 — 이 테스트가 깨지면 서버가 프레임을 조용히
버리고 대시보드만 멈춰서 추적이 어렵다.
