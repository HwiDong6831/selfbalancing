# 2026-07-29 : 센서 3개 voting

> **상태: 구현·빌드·호스트 테스트까지. 실기 검증은 아직.**

[2026-07-28](2026-07-28_balancing-standup.md) 남은 일 3번. 그때까지 MPU 3개를 달아 놓고
제어에는 mux 채널 0 하나만 썼다. 나머지 둘은 대시보드에 숫자만 띄우는 장식이었다.

---

## 왜 필요했나

읽기가 `ESP_OK` 로 성공해도 값만 깨져 오는 경우가 있다. 전송 중 비트 하나가 뒤집히면
`az` 가 16384 만큼 통째로 튄다. 반환값은 성공이므로 `fault` 로는 안 잡히고, 그대로
상보필터에 들어가 각도를 밀어버린다.

**한 개짜리 센서로는 이걸 알아낼 방법이 없다.** 값이 틀렸다는 걸 알려면 비교할 상대가
있어야 한다. 3개를 다는 이유가 여기 있다 — 중복이 아니라 상호 검증이다.

---

## 1. 비교하려면 먼저 영점을 맞춰야 한다

세 센서를 그냥 비교하면 안 된다. 개체차 때문에 정상일 때도 값이 다르다. 비교 전에
채널별 영점을 재서 빼야 한다(`measure_cal`, 1초 200샘플).

**자이로와 가속도를 다르게 다뤄야 했다.**

| | 처리 | 이유 |
|---|---|---|
| 자이로 | 측정한 영점을 **통째로** 뺀다 | 정지 상태에서 0 이어야 하는 값이다 |
| 가속도 | 세 센서 평균의 **중앙값 대비 차이만** 뺀다 | 중력이 걸려 있다. 통째로 빼면 각도 정보까지 지워진다 |

가속도까지 통째로 뺐다면 `az` 의 1g 성분이 사라지고 기울기를 못 잰다. 지워야 하는 건
물리값이 아니라 센서 사이의 어긋남뿐이다.

이 보정이 들어가면서 `measure_gyro_bias()` 가 `measure_cal()` 로 커졌고,
`balance_estimate_angle` 에 넘기던 `gx_bias` 인자는 0 이 됐다(이미 뺀 뒤라서).

---

## 2. 임계값은 재서 정했다 ★

"얼마나 벌어지면 이상치인가" 를 감으로 정할 수 없어서, 주기 로그를 편차 측정용으로
바꾸는 `SENSOR_SURVEY` 를 두고 실측했다. 정지·기울임·밸런싱 중 중앙값 대비 최대 편차:

| | 정상 편차 [LSB] | 임계값 | 여유 |
|---|---|---|---|
| 가속도 | 109 ~ 490 | **1500** | 3배 |
| 자이로 | 29 ~ 150 | **300** | 2배 |

가속도 1500 이면 2048 짜리 비트 뒤집힘도 걸린다.

**여기서 임계값을 좁히고 싶은 유혹을 참아야 한다.** 세 센서는 mux 로 전환해 가며 읽으므로
서로 약 1ms 씩 어긋난 시점의 값이다. 가만히 있을 때는 문제가 안 되지만 급변 구간에서는
1ms 차이만으로도 정상값이 벌어진다. 그 폭을 재보지 않고 조이면 **외란에 반응해야 할 바로
그 순간에 FAIL 로 멈춘다.** 안전장치가 가장 필요한 순간에 꺼지는 셈이다.

---

## 3. FAIL 은 "값이 없다" 가 아니다

판정은 셋 중 하나다.

| | 뜻 | 동작 |
|---|---|---|
| `OK` | 3개 전부 서로 일치 | 셋 평균 |
| `DEGRADED` | 1개 배제, 나머지 둘은 일치 | 둘 평균. **여전히 상호 검증됨** |
| `FAIL` | 다수결 불가 | 값 0. 호출자가 직전 값 유지 |

`DEGRADED` 가 성능 저하가 아니라는 점이 중요하다. 둘이 서로 일치하는 한 검증은 계속된다.
검증이 끊기는 건 `FAIL` 뿐이다.

**FAIL 일 때 제어를 끊으면 안 된다.** 안전 필수 분야라면 여기서 안전 상태로 전환하지만,
도립진자는 토크를 끊는 순간 넘어진다. 그래서 `tilt`/`rate`/`uq` 를 갱신하지 않고 직전
명령을 그대로 이어간다.

특히 세 개가 전부 dropout 이면 값이 전부 0 인데, `atan2(0, 0)` 이 0 이라 **"똑바로 서
있다"** 로 읽힌다. 넘어지는 중에 복원 토크가 사라지는 최악의 오작동이다. 값을 그냥
흘려보내면 이 함정에 그대로 빠진다.

### 사슬은 FAIL 이다

a~b 는 일치, b~c 도 일치, 그런데 a~c 는 불일치. 짝이 2개 나오는 경우다.
b 를 믿으면 a 도 c 도 맞고, a 를 믿으면 c 가 틀리다. **어느 쪽인지 가릴 근거가 없다.**
짝이 정확히 1개일 때만 `DEGRADED` 로 채택한다.

---

## 4. 호스트에서 테스트한다

`voting.c/h` 는 ESP-IDF 를 하나도 참조하지 않는 순수 C 로 짰다. 그래서 보드 없이 돈다.

```
gcc -Wall -Wextra -I.. test_voting.c ../voting.c -o test_voting && ./test_voting
```

15개 통과. 경계값(임계값 정확히 = 일치, +1 = 배제), 사슬, 유효 2개 불일치, 전부 dropout
같은 경우를 플래시 없이 확인할 수 있다. 판정 로직을 실기에서 재현시키려면 센서를 일부러
망가뜨려야 하는데, 그건 만들기도 어렵고 재현도 안 된다.

---

## 5. 대시보드 — 상태가 바뀌는 순간만

50Hz 로 오는 판정을 전부 남기면 볼 수가 없다. 이전 프레임과 판정이 달라질 때만 한 줄
남긴다(최근 100건).

**배제된 센서의 실제 값을 같이 남기는 게 핵심이다.** "ch1 배제됨" 만으로는 아무것도
모른다. 비트 뒤집힘처럼 크게 튄 건지, 임계값 근처에서 미세하게 어긋난 건지에 따라
할 일이 갈린다 — 앞은 I2C 문제고 뒤는 임계값 문제다.

---

## 배운 것

1. **비교하려면 먼저 영점을 맞춘다.** 그리고 물리값이 실린 축과 아닌 축은 다르게 뺀다
2. **임계값은 재서 정한다.** 감으로 좁히면 정작 필요한 순간에 오작동한다
3. **FAIL 에서 무엇을 할지가 판정 로직보다 중요하다.** 이 로봇은 멈추면 넘어진다
4. **하드웨어 의존을 안 만들면 테스트가 공짜다.** 순수 C 로 떼어 놓은 것이 15개 케이스를
   보드 없이 돌리게 해줬다
