# 2026-07-30 : 엔코더 값 손상 — 원인은 WiFi 송신 전류

> **상태: 원인 규명.** 손상의 방아쇠가 모터가 아니라 **WiFi 송신 전류**임을 확정했다.
> 완전한 해결은 [2026-08-02](2026-08-02_encoder-abz.md) — 전원 보강과 ABZ 전환.

---

## 증상

엔코더가 `raw 0` 을 반환하고 각도가 통째로 틀어진다. 그 값이 휠 속도 추정을 오염시키고,
깨진 각도로 자계를 세워 토크 방향까지 뒤집힌다.

[2026-07-27](2026-07-27_foc-noise-isolated.md) 에서 PWM 스위칭 잡음을 잡아
10kHz 로 낮췄는데도 손상이 남아 있었다. **원인이 하나가 아니었다.**

---

## 판정 : 송신 세기를 낮추자 빈도가 줄었다 ★

`esp_wifi_set_max_tx_power()` 로 송신 출력을 **20dBm → 11dBm** 으로 낮추자
손상 빈도가 눈에 띄게 줄었다.

출력을 낮추면 바뀌는 것은 **송신 순간에 끌어가는 전류**다. 통신 내용도, 버스 트래픽도,
루프 주기도 그대로다. 그 하나만 바꿔 빈도가 변했으므로 **전류가 원인**이다.

송신 순간 전류가 센서 전원을 끌어내리고, 그 전압 강하가 I2C 신호를 깨뜨린다.

공유기가 가까워(rssi −52) 11dBm 으로도 접속은 충분하다.

| 설정 | 값 |
|---|---|
| `WIFI_TX_POWER` | 44 (0.25dBm 단위 = 11dBm) |
| 기본값 | 80 (20dBm) |

## 소프트웨어로 걸러내려는 시도는 전부 실패했다 ★

### 1. 상한에 추정치를 쓰면 잠긴다

이상값 판정 상한을 `휠 속도 추정치 × dt` 로 잡았다. **한번 걸리면 안 풀린다.**

```
값을 버린다 → prev_angle 을 안 옮긴다 → 휠 속도 추정치가 얼어붙는다
  → 얼어붙은 값이 상한을 좁힌다 → 정상값까지 걸린다 → 다시 버린다
```

실측으로 **정상값을 13루프 연속 버렸고**, 그동안 커뮤테이션이 멈춰 급가속했다.

`2026-07-27` 에서 이미 같은 함정에 빠졌던 것의 변종이다. 그때 얻은 결론이
"상한에 추정치를 쓰지 말 것" 이었는데, 판정식을 손대면서 다시 들어갔다.

**고정 상한으로 되돌렸다.** 시간이 갈수록 상한이 넓어져 스스로 풀린다.

```c
#define ENC_MAX_VEL    80.0f    // 실측 최고 55 rad/s
#define ENC_BAD_FLOOR  0.30f
```

### 2. 루프 주기가 아니라 경과 시간으로 재야 한다

상한을 한 루프 예산으로 재면 **버린 직후의 정상값이 걸린다.** 값을 버리면 다음 값은
두 루프치 움직임을 담고 있기 때문이다. 이것도 연속 배제로 이어진다.

마지막으로 **채택한** 값 이후의 경과 시간(`since_ok`)으로 바꿨다.

### 3. 버리는 것 자체가 커뮤테이션을 멈춘다

값을 버리면 그 루프는 전압 벡터를 갱신하지 못한다. 손상이 잦으면 커뮤테이션이
자주 멈추고, 그게 다시 토크 충격을 만든다.

그래서 **버리는 대신 깎는** 경로를 더했다. 상한을 통과한 값이라도 휠 속도가 한 번에
튀지 못하게 각가속도로 제한한다. 깎는 것은 커뮤테이션을 멈추지 않는다.

```c
#define WHEEL_MAX_ACC  300.0f   // 실측 최대 약 120 rad/s²
```

## 곁가지 : WebSocket 연결이 굳는다

전송 도중 소켓이 사라지면 클라이언트가 `already stop` 상태로 굳어
**자동 재접속이 시작조차 안 된다.** 재접속 타이머는 클라이언트가 살아 있을 때만 돈다.

5초 넘게 연결이 안 돌아오면 클라이언트를 통째로 재시작하도록 했다.
재시작은 텔레메트리 태스크가 한다 — 이벤트 핸들러는 WS 자신의 태스크라 스스로를 못 멈춘다.

로그 전송도 고쳤다. 한 건이 실패하면 남은 것도 실패하는데, 계속 밀어넣으면
**그 실패 로그가 큐를 다시 채운다.** 첫 실패에서 중단하도록 바꿨다.

## 배운 것

1. **원인이 하나라고 가정하지 말 것.** PWM 잡음을 잡고도 손상이 남았다.
   같은 증상에 방아쇠가 둘이었다
2. **하나만 바꿔 빈도가 변하면 그게 원인이다.** 송신 출력은 전류만 바꾼다
3. **걸러내기는 원인을 못 고친다.** 임계값·재시도·필터를 세 번 시도해 세 번 다
   새 문제를 만들었다. `2026-07-27` 의 "우회책은 계측을 오염시킨다" 가 그대로 반복됐다
4. **버리는 것과 깎는 것은 다르다.** 버리면 커뮤테이션이 멈추고, 깎으면 안 멈춘다
