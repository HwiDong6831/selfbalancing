# 2026-07-21 : I2C 버스 멈춤 → 워치독 리셋 해결 (레거시 드라이버 이관)

밸런싱 통합 테스트 중, 모터 동작 시 I2C가 멈추며 재부팅되는 문제를 추적·해결한 기록.

---

## 증상
```
W i2c.common: GPIO 16/17 is not usable, maybe conflict with others
rst:0x7 (TG0WDT_SYS_RESET)
WDT rst info: PRO CPU PC=... _xt_lowint1   ← CPU0가 인터럽트에 갇힘
```
- 워치독 리셋(brownout 아님). CPU0가 인터럽트 처리 중 갇혀 워치독이 강제 리셋.
- "GPIO not usable" 경고는 원인이 아니라 결과 (I2C timeout 후 드라이버 버스복구 시 GPIO 재설정).
- 가끔 즉시, 가끔 한참 뒤 → 확률적.

## 진단 과정

### 1. 범인 격리
| 구성 | 결과 |
|---|---|
| foc+encoder+mpu 다 주석 | 정상 |
| foc(모터) 주석, encoder+mpu | 리셋 |
| foc+encoder, **mpu만 주석** | **정상** |
→ 범인은 **MPU(mux) I2C 경로**.

### 2. mux 전환이 방아쇠
- `mpu6050_read_accel`이 매 호출 `mux_select`(0x70 쓰기) 수행.
- mux를 루프 전 1회만 선택 → 리셋 사라짐 → **반복 mux 쓰기가 버스 글리치 유발**.

### 3. 전원/모터 상관 → PWM 스위칭 EMI 확정
- 배터리 OUT(드라이버 전원X): 경고만, 계속 동작.
- 배터리 IN: 리셋. 단 **모터 기계적 회전과 무관** (안 돌아도 리셋, 돌아도 멀쩡할 때 있음).
- **FOC 완전 주석(PWM 스위칭 없음) → 리셋 전혀 안 남.**
- → 진짜 방아쇠는 **드라이버 22kHz PWM 스위칭 EMI**. 확률적으로 I2C 트랜잭션과 겹칠 때 버스 오염.

### 4. 하드웨어는 이미 양호
- 배터리(-) 진짜 스타 그라운드(SimpleFOC/스텝다운 각각 분기), SimpleFOC 전원부 1000µF 벌크 캡.
- 모터 3상선 독립 핀. I2C 10cm(단면 만능기판, 못 줄임).
- 100kHz로 낮춰도 동일 → 엣지속도/풀업 마진 문제 아님.

### 5. 결정적 단서 — 아두이노는 같은 HW에서 됐음
- 동일 하드웨어(mux+3MPU+MT6701, I2C 16/17)로 **아두이노에선 3센서 평균+모터 동시 동작 정상**(진동·리셋 없음).
- 옛 커밋의 남의 참조코드는 MT6701을 ABZ로 쓴 다른 구성이었지만, 본인 아두이노 코드는 같은 무거운 I2C 구성이었음.

## 근본 원인
**ESP-IDF 새 `i2c_master` 드라이버가 노이즈로 stuck된 버스에서 CPU를 인터럽트에 가둠 → 워치독 리셋.**
- 글리치(EMI)는 아두이노에도 있었으나, **아두이노 Wire는 stuck 시 타임아웃 후 넘어감**(CPU 안 멈춤).
- ESP32 Arduino Wire는 내부적으로 **ESP-IDF 레거시 i2c 드라이버(`driver/i2c.h`) 기반** → 이게 견딘 이유.
- 즉 하드웨어 EMI 문제이자, **새 드라이버가 글리치에 취약한** 문제.

## 해결 — 레거시 `driver/i2c.h`로 이관
- `i2c_new_master_bus`/디바이스 핸들 → `i2c_param_config` + `i2c_driver_install` + 포트 직접 접근.
- 읽기/쓰기: `i2c_master_write_to_device`, `i2c_master_write_read_device`.
- 버스 stuck 시 **CPU 행 없이 `ESP_ERR_TIMEOUT` 반환** → 그 샘플만 버리고 이전값 유지로 계속.
- 대상: `main.c`, `mpu6050.c/.h`, `encoder.c/.h`, 각 CMakeLists(`esp_driver_i2c`→`driver`).
- 유지: mux 전환 후 settle 500µs, 실패 시 이전값 유지, voting 준비.
- 참고: 레거시 API는 v5.5에서 deprecated 경고(빌드는 정상). 새 드라이버 CPU 행 이슈 회피 목적.

## 시도했으나 부족했던 것 (기록용)
- settle 지연 추가 / 이전값 유지 → 배터리 OUT은 견디나 IN(스위칭)은 여전히 리셋.
- 실패 시 `i2c_master_bus_reset` 통제 복구 → 행이 드라이버 콜 내부에서 나 도달 못 함.
- `I2C_TIMEOUT_MS` 100→10 → 호출이 타임아웃 무시하고 행 → 무효.
- → 전부 새 드라이버 한계. 드라이버 교체가 정답이었음.

## 곁다리로 잡은 버그 (별도 커밋)
- FOC 첫 iteration `uq` 폭발: `main.c` `prev_angle` 실제값 초기화 + `uq` ±V_SUPPLY 클램프.
- `uq: nan`: `dt=0`일 때 `0.0f*inf=nan` (balance.c의 KD항) → 루프 전 delay로 첫 dt 0 방지.

## 검증
- 빌드 성공(경고만), 실기 테스트 **리셋 이상 무**. I2C 문제 종료.

## 남은 문제 (다음 작업)
1. **반응 0.1초 지연 → 넘어짐** : 자이로(각속도) 미사용. `mpu6050_read_accel`이 가속도만 읽고 자이로(0x43) 안 읽음. balance는 가속도 raw만 P제어(KD=0). → 자이로 추가(상보필터+각속도항) 또는 아두이노식 상태피드백(토크모드) 필요.
2. **양수 uq에서만 진동/소음** : FOC 커뮤테이션 비대칭. 극쌍수/정렬 오프셋/인코더 방향 의심. 오픈루프 양방향 테스트로 원인 격리 예정.
