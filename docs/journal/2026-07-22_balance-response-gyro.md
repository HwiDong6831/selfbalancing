# 2026-07-22 : 밸런싱 반응속도 개선 (1) — 자이로 + 상보필터 각도 추정

I2C 문제 해결 후 실기 테스트에서 드러난 "반응 지연" 문제를 추적하고,
1단계로 자이로 기반 각도 추정을 구현한 기록.

---

## 문제
- 기울어지고 ~0.1초 뒤에야 휠이 반응 → 못 잡고 넘어짐.
- (별개) target_vel/uq 양수일 때 진동·소음 — 다음 작업으로 미룸.

## 원인 (반응 지연)
전송 지연 아님(센서→구동 한 루프 10ms 내). 제어 구조·게인 문제:
1. **속도 캐스케이드** : tilt로 목표 "속도"를 정함 → 휠이 목표속도 도달하면 error→0 → uq→0 → **복원 토크 사라짐**. 밸런싱은 지속 복원 토크 필요.
2. **각속도(자이로) 미사용** : `read_accel`이 가속도만 읽고 자이로 안 읽음. 각도가 커진 뒤에야 반응 → 늦음.
3. **게인 과소** : `target_vel = 0.2·error/150`. 8° 기울어야 겨우 3V.
4. **가속도 단독** : 모터 진동·선형가속에 오염.

## 접근
- 최종은 아두이노 검증 구조(상태피드백 토크모드): `uq = K1·angle + K2·gyro (+K3·휠속도 +K4·휠위치)`.
- **Phase A** (센서 1개로 제어부터 세우기) → **Phase B** (MPU 3개 voting) 로 분리.
- Phase A 하위단계: ① 자이로 읽기 → ② 상보필터 → ③ 토크제어.

## 한 것 (① ②)

### ① 자이로 읽기
- `mpu6050_read_accel_gyro()` : 0x3B부터 14바이트 버스트(가속도6+온도2+자이로6) 한 트랜잭션.
- 자이로 기본 ±250°/s = 131 LSB/(°/s).

### tilt 축 실측
- 로봇 기울여 로그 확인 → **각도=ay, 각속도=gx**.
- 정지 시 자이로 bias(평균 offset): gx ≈ 100~130 LSB (≈1°/s). noise 아니라 bias → 시작 시 평균 빼서 보정.
  (gy≈320은 안 쓰는 축이라 무관했음.)

### ② 상보필터
- `balance_estimate_angle()`:
  - `accel_angle = atan2(-ay, -az)` [deg], `rate = (gx - gx_bias)/131` [deg/s]
  - `angle = 0.98·(angle + rate·dt) + 0.02·accel_angle`
- **wrap 문제 해결** : 똑바로 선 자세가 하필 atan2 ±180° 경계 → 제어 setpoint가 불연속점.
  `-ay,-az`로 **180° 이동** → 똑바로=0, 동작범위(±60°)가 경계에서 멀어짐. 상수 이동이라 각속도 부호 영향 없음.
- `main.c` : 시작 시 gx_bias 자동 측정(정지 200샘플 평균), 루프에서 추정 후 로그 검증.

## 검증
- 정지: angle 안정, 드리프트 없음.
- 기울이면 즉시 추종(지연 없음).
- 똑바로 → 0, 좌우 굴려도 `+60→0→-60` 연속(경계 점프 없음).
- ※ 추정 각도는 아직 **제어엔 미사용**(옛 속도제어가 모터 구동 중). 로그 검증만.

## 남은 작업
1. **③ 토크제어** : `uq = K1·angle + K2·rate` (angle=0 목표), foc에 토크 인가 함수(속도 PID 우회), K1/K2 튜닝. 부호 주의(반대면 즉시 넘어짐).
2. **Phase B** : MPU 3개 voting (센서별 bias 보정, 매 루프 3채널 read).
3. (별개) FOC 양수 uq 진동/소음.
