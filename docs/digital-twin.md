# 디지털 트윈

모바일 웹에서 로봇의 현재 자세를 실시간 3D로 확인하는 기능.

## 1. 목적

- 실제 기기의 자세를 모바일 화면의 3D 모델에 실시간 반영한다.
- 센서 결함 시뮬레이션 시 자세 변화를 시각적으로 검증하는 도구로 사용한다.
- 기존 모바일 Wi-Fi 제어 기능(FR-6)과 동일한 웹 UI에 통합한다.

## 2. 자세 데이터

### 자세 소스

- **가속도 센서(MPU6500)만 사용.** 엔코더 휠각은 포함하지 않는다.
- Voting 알고리즘을 통과한 융합 자세 1개를 송신한다.

### 표현 방식 — 쿼터니언

자세는 **쿼터니언(quaternion)** 으로 송신한다.

**선택 이유: 짐벌락(gimbal lock) 회피.**
Euler 각(roll/pitch/yaw)은 특정 자세에서 두 축이 겹치며 자유도가 소실되는 짐벌락이 발생한다. 밸런싱 로봇은 자세 변화 범위가 넓어 짐벌락 위험이 있으므로, 이를 원천적으로 피할 수 있는 쿼터니언을 채택한다. 쿼터니언은 보간(SLERP) 시에도 부드러워 3D 렌더에 유리하다.

### 페이로드

- 쿼터니언 4성분 `(w, x, y, z)`.
- 송신 주기: 약 20~50Hz (대역폭과 렌더 부드러움 절충, 실측 후 조정).

## 3. 통신

- 프로토콜: **WebSocket** (저지연 연속 스트림, HTTP 폴링 대비 적합).
- 경로: **ESP32 → Spring 서버 → 브라우저**. ESP32 는 서버가 아니라 클라이언트다.
- 기존 모바일 제어 채널과 동일한 Wi-Fi 연결 재사용.

> 처음에는 ESP32 가 직접 WebSocket 서버가 되는 안이었으나, ESP32 부담과 동시 접속 수
> 때문에 Spring 서버가 중계하는 구조로 바꿨다. 근거는 [server.md](./server.md) 3장.

## 4. 모바일 3D 렌더

- 웹 기반 렌더링: **Three.js / WebGL**. 앱 설치 불필요.
- 웹 자산 호스팅: **별도 서버**. (모바일 컨트롤 UI도 앱 대신 웹으로 제공, ESP32 온보드 flash 미사용.)
- 3D 모델: **기존 프레임 export 재사용** (`docs/frame/obj/*.obj` — front/back/wheel 등). 신규 제작 없음.
- 수신 쿼터니언을 모델 mesh 회전에 직접 적용.

## 5. 결함 시뮬레이션 연동

- 트윈 화면에 센서 상태 오버레이: 어느 센서가 faulted 인지, voting 결과 표시.
- 결함 주입 시 자세 흔들림을 3D로 시각 확인 → 검증 도구 역할.

## 6. 구성요소

| 계층 | 구성요소 |
|------|----------|
| ESP32 | WebSocket 클라이언트 (`espressif/esp_websocket_client`) |
| 자세 소스 | 가속도 센서 융합 자세(voting 통과), 쿼터니언 출력 |
| 별도 서버 | Spring Boot — 중계 + 웹 자산(HTML/JS) 호스팅 |
| 모바일 웹 | Three.js 3D 렌더, WebSocket 클라이언트 |
| 3D 모델 | `docs/frame/obj/*.obj` 재사용 |

## 7. 미결 사항

- 쿼터니언 송신 주기 최종값 (실측 후 결정). 텔레메트리는 현재 50Hz 로 보내는 중.
- 센서 상태 오버레이 UI 상세.

서버 스택은 Spring Boot 로 정해졌고 대시보드까지 동작한다 ([server.md](./server.md)).
남은 것은 쿼터니언 송신과 3D 렌더다.
